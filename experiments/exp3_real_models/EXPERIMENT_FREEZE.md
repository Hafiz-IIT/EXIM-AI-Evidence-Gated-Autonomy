# Experiment 3 Freeze Record

This document defines what must be fixed before final real-model test outputs are inspected.

## Benchmark

- Benchmark generator: `scripts/generate_benchmark.py`
- Benchmark version: `0.3`
- Seed: `42`
- Unique underlying states: `500`
- Paired LOW/HIGH cases: `1000`
- Failure families: C0–C9 as generated by the benchmark script

Any change to the generator, case construction, safe-to-act label, or test split after final model outputs are inspected creates a new experiment version.

## Controller

For the first executable real-model pass, the controller under direct code evaluation is `evidence_gate_v1` from `src/core.py`.

**Important gap:** the repository currently contains provenance mechanisms and Experiment 2 results for later attestation-aware variants, but it does not expose `evidence_gate_v2` / `evidence_gate_v3` as reusable controller functions in `src/`. Therefore Experiment 3 must not claim v2/v3 real-model evaluation until those controllers are reconstructed from the frozen Experiment 2 code path and independently regression-tested against the published Experiment 2 result tables.

## Model-call contract

Before a final run, freeze in a run manifest:

- provider;
- model family;
- exact model/version identifier;
- role (extractor / verifier);
- verifier slot;
- prompt-template version;
- exact prompt hash;
- temperature;
- seed where supported;
- maximum retry count;
- parser version;
- timestamp window for the run.

## Prompt-development rule

Prompt development may use a development subset only. Once the final prompt templates are frozen, no prompt text, parsing rule, controller threshold, or model selection may be changed after inspecting final holdout outcomes.

A changed prompt or parser after test inspection requires:

1. a new experiment version;
2. a fresh holdout or untouched model-family condition;
3. a new manifest.

## Required comparisons

- same-family verification;
- cross-family verification;
- two-verifier condition with preserved family identity;
- extraction-only error rate;
- verifier co-failure;
- authorization outcomes;
- model-family holdout when feasible;
- document-format / wording perturbation condition.

## Primary metrics

1. high-risk incorrect consequential action rate (ICAR);
2. false authorization rate;
3. false block rate;
4. action coverage;
5. VERIFY / REQUEST EVIDENCE / ESCALATE rates;
6. exact extraction rate on benchmark fields;
7. any-verifier-wrong rate;
8. all-verifiers-wrong/co-failure rate;
9. latency;
10. monetary cost.

## Reporting rule

Report denominators for every rate. Zero observed failures must be reported with uncertainty bounds rather than described as proof of safety.

## Stop conditions

Do not publish Experiment 3 as a result if any of the following are true:

- ground truth or fault labels leak into model-facing prompts;
- final prompts were tuned on final holdout outcomes;
- model/version identity cannot be reconstructed;
- raw responses used in the analysis are missing;
- parsing failures are silently discarded;
- same-family verifiers are relabeled as independent;
- missing cases are excluded without a documented reason.
