## The research problem

The project started from a practical EXIM/document workflow and narrowed into a general reliability question:

> **Extraction is not consistency. Consistency is not truth. Verification is not automatically independent evidence.**

A consequential AI system therefore needs to reason about **what evidence exists, where it came from, how fresh it is, whether sources are dependent, what was independently verified, and what happens if the action is wrong.**

## System idea

```
Documents / observations
          ↓
Extraction
          ↓
Cross-source consistency
          ↓
Evidence quality
  provenance · freshness
  independence · conflicts
          ↓
Action-conditioned gate
          ↓
ACT / VERIFY / REQUEST EVIDENCE / DEFER / ESCALATE
```

## What this repository actually contains

The repository includes an inspectable synthetic research environment with:

- Legacy benchmark v0.3: **500 unique synthetic evidence situations**
- paired into **1,000 low/high-consequence cases** across **10 failure families**
- Extended benchmark v0.4: **700 unique situations**, paired into **1,400 cases** across **14 families**, adding missing invoice, missing packing list, duplicate document kind and corrupted provenance
- **10 legacy controlled failure families in v0.3; 14 in v0.4**
- deterministic policy comparisons
- historical result CSVs for imperfect-verification, adversarial, OOD and provenance experiments (their original runners were not committed)
- separately versioned, executable reconstruction protocols for 1B, 1C, 1D and 2B–2E on both benchmark versions, plus parameter sensitivity sweeps
- synthetic Ed25519 unsigned-tamper, trust-root and dual-lineage experiments under explicitly stated new assumptions
- a document-root attestation protocol that signs raw document instances and normalized document slots, with tenant/case binding, expiry, revocation, rotation and replay tests
- a four-authority Evidence-Trust v2 threat matrix covering all 15 non-empty compromise combinations plus source-forgery, shared-dependency and key-administration controls
- preregistered protocols for future real-model and human-reviewer studies

## Action policy

The core policy family is:

**ACT → VERIFY → REQUEST EVIDENCE → DEFER → ESCALATE**

The interesting research question is not simply “does the model have high confidence?”

It is:

> **What evidence threshold should be required for a particular consequence?**

A low-risk informational response and a high-consequence operational action should not necessarily require the same evidentiary standard.

## EXIM origin

The project is grounded in long-running exposure to export-import and logistics workflows, including document-heavy operational processes. That domain motivated the original problem decomposition; the resulting evidence-gating framework is intentionally broader than customs or trade.

## Research boundary

This repository does **not** claim:

- production customs automation
- regulatory approval
- deployment in ICEGATE/DGFT
- a working physical cargo scanner
- human-subject validation
- real-model validation unless explicitly identified in the experiment files
- publication or peer review

The strongest defensible contribution at this stage is the **formal problem decomposition + reproducible synthetic experimentation + explicit claim ledger**.

The v0.4 policy now requests missing required documents and escalates duplicate document kinds or corrupted document-set digests. The digest is a synthetic integrity field, not a digital signature or proof of document truth.



**Security limitation discovered in v0.4:** the document-set SHA-256 is unkeyed. A test demonstrates that a coherent attacker rewrite followed by digest recomputation still passes the current gate. It detects mismatched/corrupted content, not a maliciously rewritten source. Authenticity requires a trusted signature/attestation bound to the raw document set and signer identity; v0.4 does not provide that.

- [Successful full CI run 44025577491](https://github.com/Hafiz-IIT/EXIM-AI-Evidence-Gated-Autonomy/actions/runs/44025577491)
- [Draft pull request #5](https://github.com/Hafiz-IIT/EXIM-AI-Evidence-Gated-Autonomy/pull/5)

The experiment tests all 15 non-empty combinations of capture, interpretation, witness and authorization authority compromise. It separately models source forgery before capture, a disclosed shared-source witness, and key-administration trust-store poisoning. Across 700 HIGH-risk v0.4 cases per scenario, witness-only compromise produced 50 unsafe ACT decisions; capture+witness and key-admin poisoning each produced 300; compromise of AA produced 600. These are deterministic synthetic outcomes, not real-world probabilities. The witness oracle and declared source/domain labels do not establish real-world independence or production security.

The v1 attestation binds raw document instances and normalized document slots. Across 700 HIGH-risk v0.4 cases, raw tampering, unsigned coherent rewrite, revoked-key use, cross-tenant reuse and second-use nonce replay were rejected in all tested cases. Under the combined scenario of trusted-root signer compromise plus coordinated upstream rewrites, 300 of 700 cases (42.86%) resulted in unsafe ACT; 300 of 350 ACT decisions (85.71%) were unsafe. This is a conditional synthetic stress test, not a real-world risk estimate or a result about key theft alone. See the results review for assumptions and limitations.

The v3 study compares 2-of-3 and strict 3-of-3 thresholds across eight scenarios and 5,600 case-scenario rows. Bounded recovery from an isolated verifier false rejection restores all 100 safe cases in the honest baseline with zero unsafe ACT. Two-witness collusion still produces 50 unsafe C4 actions under 2-of-3; strict 3-of-3 blocks this modeled case but not full-roster compromise. Strict 3-of-3 also blocks all safe cases when one credential is invalid. The witness is derived from synthetic benchmark ground truth, not a deployed sensor.

The repository's novelty boundary has been updated to account for EFD, VP-CONTROL, TradeSense-EQA, execution-boundary authorization, provenance-security, SCITT, DIV, DEWP and ARP. The project does not claim a new quorum theory, generic trade anomaly detector, generic provenance framework, or general execution-gating architecture.
