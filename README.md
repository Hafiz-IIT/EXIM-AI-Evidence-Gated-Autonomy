## The research problem

The project started from a practical EXIM/document workflow and narrowed into a general reliability question:

> **Extraction is not consistency. Consistency is not truth. Verification is not automatically independent evidence.**

A consequential AI system therefore needs to reason about **what evidence exists, where it came from, how fresh it is, whether sources are dependent, what was independently verified, and what happens if the action is wrong.**

## System idea

```
Documents / observations
          ↓
Extraction
          ↓
Cross-source consistency
          ↓
Evidence quality
  provenance · freshness
  independence · conflicts
          ↓
Action-conditioned gate
          ↓
ACT / VERIFY / REQUEST EVIDENCE / DEFER / ESCALATE
```

## What this repository actually contains

The repository includes an inspectable synthetic research environment with:

- Legacy benchmark v0.3: **500 unique synthetic evidence situations**
- paired into **1,000 low/high-consequence cases** across **10 failure families**
- Extended benchmark v0.4: **700 unique situations**, paired into **1,400 cases** across **14 families**, adding missing invoice, missing packing list, duplicate document kind and corrupted provenance
- **10 controlled failure families**
- deterministic policy comparisons
- historical result CSVs for imperfect-verification, adversarial, OOD and provenance experiments (their original runners were not committed)
- separately versioned, executable reconstruction protocols for 1B, 1C, 1D and 2B–2E on both benchmark versions, plus parameter sensitivity sweeps
- synthetic Ed25519 unsigned-tamper, trust-root and dual-lineage experiments under explicitly stated new assumptions
- preregistered protocols for future real-model and human-reviewer studies

## Action policy

The core policy family is:

**ACT → VERIFY → REQUEST EVIDENCE → DEFER → ESCALATE**

The interesting research question is not simply “does the model have high confidence?”

It is:

> **What evidence threshold should be required for a particular consequence?**

A low-risk informational response and a high-consequence operational action should not necessarily require the same evidentiary standard.

## EXIM origin

The project is grounded in long-running exposure to export-import and logistics workflows, including document-heavy operational processes. That domain motivated the original problem decomposition; the resulting evidence-gating framework is intentionally broader than customs or trade.

The v0.4 policy now requests missing required documents and escalates duplicate document kinds or corrupted document-set digests. The digest is a synthetic integrity field, not a digital signature or proof of document truth.



**Security limitation discovered in v0.4:** the document-set SHA-256 is unkeyed. A test demonstrates that a coherent attacker rewrite followed by digest recomputation still passes the current gate. It detects mismatched/corrupted content, not a maliciously rewritten source. Authenticity requires a trusted signature/attestation bound to the raw document set and signer identity; v0.4 does not provide that.
